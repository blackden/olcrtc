# Phase B — простым языком

Этот документ объясняет, что было сделано в [PR #6](https://github.com/blackden/olcrtc/pull/6), без жаргона. Технические детали — в `principles.md`, `ghcr.md`, `mikrotik-chr.md`.

## Что было

Два отдельных файла для запуска через docker (один для сервера, один для клиента). Docker-образ собирался с базовыми настройками, проверка «жив ли контейнер» была примитивной (просто проверка, что процесс не сдох), образ нигде не публиковался — каждый собирал сам. И никаких инструкций про роутер MikroTik.

## Что стало

### 1. Один файл вместо двух — `compose.yaml`

Раньше: `docker-compose.server.yml` отдельно, `docker-compose.client.yml` отдельно.

Теперь: один `compose.yaml`, и ты выбираешь профиль:

```bash
docker compose --profile client up   # клиент
docker compose --profile server up   # сервер
```

Плюс к нему — все «правильные» настройки безопасности: контейнер не может писать в свою файловую систему, лишён всех привилегий, не может запросить root, ограничен по памяти/CPU/процессам, логи автоматически ротируются. Ключ шифрования больше не торчит в env-переменных (где его видно через `docker inspect`), а лежит в отдельном файле в папке `secrets/`, которая никогда не попадёт в git.

### 2. Сборка стала повторяемой

Раньше: `FROM alpine:3.22` — Alpine 3.22 завтра может быть другой версии (с фиксами безопасности), и сборка покажет другие байты.

Теперь: явно прибито к конкретному «снимку» образа (`sha256:...`), и все системные пакеты внутри (ffmpeg, ca-certificates и пр.) тоже прибиты по версиям. Через год собрав то же — получишь те же байты. Это важно для аудита и воспроизведения багов.

### 3. Health-check теперь реальный

Раньше: «процесс `olcrtc` есть в системе → значит OK». Это не проверка, это просто пинг трупа.

Теперь:
- **Для клиента:** пробуем подключиться к локальному SOCKS5-порту изнутри контейнера. Если порт не отвечает — контейнер красный.
- **Для сервера:** пока остался `pidof` (для нормальной функциональной проверки сервера нужно править Go-код, отдельная задача).

### 4. Образ собирается в облаке (приватно)

Раньше: чтобы пользоваться образом, надо клонировать репо и собирать у себя.

Теперь:
- При каждом коммите в `blackden/master` GitHub Actions автоматически собирает образ под `linux/amd64` и пушит на `ghcr.io/blackden/olcrtc`. ARM64-сборка парковано в workflow (комментарии) — включается одной правкой, когда понадобится.
- Образ **приватный** — флип на public необратим, поэтому решили не делать. Чтобы скачать, нужен `docker login ghcr.io` с PAT (scope `read:packages`).
- Если когда-нибудь понадобится публичный доступ — будем зеркалить в Docker Hub отдельным workflow (`docker.io/blackden/olcrtc`), а GHCR оставлять источником истины.
- Образ подписан, есть SBOM (список всех библиотек внутри) и provenance-аттестация.

### 5. Инструкция для MikroTik

RouterOS 7.4+ умеет запускать docker-контейнеры прямо на роутере (через свой пакет `container`). Теперь есть:

- `docs/blackden/mikrotik-chr.md` — подробный пошаговый текст на русском: как включить, как настроить сеть (veth + bridge + NAT), как пробросить SOCKS5 в твою LAN, что ломается и почему.
- `script/mikrotik/install.rsc` — готовый скрипт: открываешь, меняешь 5 переменных в начале (ключ, room_id, диск), импортируешь в роутер — он сам всё разворачивает.

### 6. Claude научился не забывать правила

- В `.claude/skills/fork-workflow.md` записан свод правил для работы в этом репо (не коммитить в master, формат коммитов, как обращаться с секретами, гонять lint перед commit'ом). Это «скилл» — он автоматически подтягивается в любую следующую сессию Claude.
- Запомнили принцип «качество важнее скорости» — больше не глушим ворнинги `hadolint` директивой `ignore`, а чиним причину (как с пинами apk-версий: было желание просто подавить, но Claude зарезолвил реальные версии).
- Запомнили: тянуть свежую документацию через context7 / WebSearch (полезно — версии GitHub Actions в памяти Claude были устаревшие, context7 показал, что уже v7/v6/v4).

## Что осталось сделать руками

1. **Замержить PR [#6](https://github.com/blackden/olcrtc/pull/6).** Автоматически закроет issues #1–#5.
2. **После merge** GitHub Actions сам соберёт образ и положит на GHCR. Образ останется **приватным** — это сознательное решение (флип на public необратим, не делаем). Чтобы пользоваться образом, нужен PAT с `read:packages` и `docker login ghcr.io`. См. [`ghcr.md`](ghcr.md).
3. *(Опционально, future work)* Зеркало в Docker Hub для публичного доступа, подпись через cosign, скан Trivy, автообновления Renovate, slim без ffmpeg.
